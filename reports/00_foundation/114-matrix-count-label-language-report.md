# Matrix Count Label Language Report

## TASK
Remove duplicate / confusing `x` usage across `/operator/matrix` so `x` means sizing multiplier only.

## WHAT I CHANGED
- Replaced count-as-`x` labels across the Matrix page with semantic count nouns:
  - `jams` for AOF action / position rows,
  - `spots` for review candidates, runout guardrails, and position result rows,
  - `folds` for fold exposure rows,
  - `opens`, `3bets`, and `squeezes` in the sizing table.
- Updated pinned detail pills from labels like `HJ · Iso vs limper(s) · 1x` to `HJ · Iso vs limper(s) · 1 spot`.
- Updated backend-generated Matrix interpretation text so single jam samples are described as `a single jam/all-in outcome`, not `1x jam/all-in`.
- Updated result summary prose from `countx` format to `count spots`.
- Kept `x` only where it means sizing or chart structure:
  - `2.1x` open size,
  - `6.35x` 3bet size,
  - `2x` open reference,
  - `13x13` Matrix name.
- Widened the AOF count column so labels like `368 jams` fit better.
- Added render QA assertions so Matrix count labels fail if they regress to `number+x`.

## ARCHITECTURE IMPACT
- Minimal backend impact: only deterministic explanation strings changed.
- No parsing, scoring, persistence, or Matrix payload fields changed.
- Frontend product language is now more consistent and less ambiguous.

## DECISIONS MADE
- `x` is reserved for bet-size multipliers and `13x13`.
- Counts always use nouns.
- `spots` is the default noun for hand/action observations when the count is not specifically opens, jams, folds, 3bets, or squeezes.

## RISKS / OPEN QUESTIONS
- Some mobile pinned-detail table rows are still dense and can wrap, but they no longer misuse `x` for counts.
- Future copy generated by new backend cards should follow the same rule.

## OUT OF SCOPE
- No redesign of the Matrix cell grid.
- No backend metric recalculation.
- No new filters or interaction behavior.
